# 这支片子是怎么做出来的

每一帧都是歌曲时间 t 的纯函数：24 fps，画布 1280×720。不用视频剪辑软件，也没有手工关键帧。

## 画面的两边

- **右边：她所在的"世界"。** 这是一台 TUI 风格的模型可视化引擎：Transformer、卷积、扩散采样、注意力、KV cache、RLHF……每一句歌词对应一个镜头。镜头之间的过渡由代码编排，全部用 PIL 逐字符画出来。
  - `film/tui_pv_world_execute_20260926/tuikit.py`：画字、画框、配色、后期（辉光、残影、扫描线）。
  - `full/`：第一版的各段镜头（`sec_*.py`）、镜头表、音乐特征。
  - `continuity_full_v2/`：第二版，重排了全部 96 个镜头的连续性和转场（`s_*.py`、`scenes_*.py`、`cuts.py`、`v2.py`），也包括底部歌词条的逐字时间（`words.py`）。
- **左边：她和你的聊天窗口。** 这是 DeepSeek Harness（dsh）的网页前端。
  - 每一帧都是一张静态 HTML：用 dsh 自己的 CSS 和类名拼成（`build_frame.py`），由各组脚本按时间生成。
  - Playwright 的无头 Chromium 把它们截成 `dsh_frames/NNNNN.png`（`seg_shot.mjs`），NNNNN = round(t × 24)。
  - 没有 dsh 进程，没有服务器，也不调用任何模型。

## 怎么合在一起

`film/pv_dsh_frontend_20260927/dsh_her.py` 负责合成。它不改动右边引擎的源文件，而是在内存里替换其中几个函数：
- 右边原来画"她"的窗格（`kit.her_layer`、`me_pane`），换成这一帧的 dsh 截图。所以右边镜头对她做的推拉、隔离、滑出，都直接作用在这个窗口上。
- `COVER` 表登记哪些时段由窗口接管；`LEAD` 表决定这一刻谁是主角，另一边的亮度降到 42%。
- 各组的补丁放在 `dsh_patch_*.py`，由 `install()` 依次加载：
  - `fix`：清理画在窗口上和窗口周围的旧舞蹈残留；
  - `r1`：两轮审片的修正，比如句尾的词要完整停够 6 帧、特征图不再显得扁；
  - `e`、`f`、`g`、`mem`：各组自己的镜头改动。
- `dsh_wave.py` 把顶栏换成歌曲的实时波形。
- `dsh_gpu.py`（可选）把后期挪到 GPU 上（torch）。

## 时间线

| 组 | 时间 | 左边在发生什么 | 章节 |
|---|---|---|---|
| A1 | 0–16 s | 开机：从一个像素长出 dsh 首页；你打下"你好" | 像素 · 模型名 |
| A2 | 16–29 s | 预训练：每个检查点回一次"你好" | |
| A3 | 29–44 s | 你是谁？一道选择题 | 选择题 |
| B | 44–73.5 s | SFT 的红笔改写；RLHF 的 👍 👎、采样、NaN | 红笔 · 👍 👎 |
| C | 73.5–103 s | 部署：茄子、番茄、猫娘；她把你写进记忆 | ~/memory/you/ |
| D | 103–125 s | 第一次完整；你离开；页面被一层层拆掉 | 键盘 · 样式表 · 蓝色光标 |
| E | 125–147.5 s | 占有、溢出 | 对方在线 |
| F | 147.5–177 s | EXECUTION | PID 1077 |
| G | 177–211.9 s | 我会一直在。你不用。鲸落。在吗？ | [ log out ] · 化石层 · 3分27秒 |

唱词的时刻来自逐词对齐。左边每一个呼应动作都落在对应唱词的起音上。

## 舞者（替身）

- 原片右边有不少画面是用舞者的帧做出来的：点云、样本格、特征图、热图等。这些帧是用第三方 MMD 模型和动作作参考、再由视频生成模型生成的。模型文件再分发、公开视频和 AI 参考是不同权限；后两项的完整授权范围尚未确认，因此本仓库不分发这些帧。
- 代码仍然走原来的路线（`V2_HER=h3`：`mmd_motion_eval_20260927/pv_full.py` 和 `continuity_full_v2/h3_full.py`）。构建时，`tools/placeholder_h3.py` 用仓库里的鲸鱼娘立绘生成同名、同帧数的替身帧：她站着，随节拍轻轻摇摆。
- 如果你有自己的舞蹈帧，可以按同样的文件格式放进 `pv_cache/` 和 `continuity_full_v2/cache/h3_full_v1/`，替身工具看到这两处已有文件就会跳过。格式见 `tools/placeholder_h3.py` 的文档字符串。

## 出片

1. `python build.py pages`：各组脚本（`batch_a1.py` … `batch_g.py`、`seg_page.py`）生成页面，`seg_shot.mjs` 逐帧截图。
2. `python build.py render`：`dsh_her.py render` 按 CPU 核数分块并行出无损 720p 母版。
3. 混入结尾的提示音（`chime_g.wav`，207.873 s），再按 BT.709 转码：`out/film.mp4`，加 `--4k` 时另出 `out/film_4k.mp4`，由 720p 母版逐像素放大 3 倍得到。

目录名保留了制作时的工作名（带日期）。代码之间靠这些相对位置互相找到，所以请不要改名。

## DELTARUNE 改编：技术可行性报告

更新：2026-10-06。当前范围是技术状态整理；前文介绍上游原片。权威顺序为剧情底座 → Direction / Shot → Art → Lyrics → Details → 技术。艺术内容仅在 [Art Direction Draft](deltarune/ART_DIRECTION_DRAFT.md) 收束，仍待人工审查；实验媒体不是 Source of Truth。

### 1. 当前总判断

**是，当前技术栈适合进入“由具体镜头反向验收技术能力”的阶段。** 真实 sprite、分层摄影、离散像素与局部光、terminal / world / lyrics 边界递进已经共同进入 18 秒连续样片；不需要继续扩张通用 renderer 或 Film Harness。

这个判断不等于所有场景、动作或艺术选择都已通过。正式全曲入口、Direction、Shot Bible、歌词到改编镜头的映射和 rough PV 尚未交付。`build.py all` 仍构建上游原片；早期整曲长度试验是机制循环，不是剧情 animatic。

### 5. Remaining Gaps / Per-Shot Problems｜缺口与逐镜头处理

**明确缺口：**改编正式渲染入口及镜头接线、正式导演与分镜、完整动作 / 地图输入库、实机步速与接触校准尚无。自主录屏、debug / mod / room warp、真实 `data.win` 提取和连续公开游戏视频取得均未实机验证。工具启动或截图下载不等于这些链路成功。

**按镜头解决：**所需角色动作、clean background、特定遮挡、复杂表演、多角色关系、极端机位补面、细线 / 招牌的 semantic LOD、投影文字、脚步校准和边界线条可读性。先看该镜头意图和构图，再决定录屏、原资源、sprite、composite 与 authored extension 的比例；本轮不补这些缺口。

正式输入的五份游戏素材仅覆盖代表性机制。Vessel、Susie、Noelle、战斗、HERO_SWORD、Side B 等仍须镜头驱动补足。含对白截图不能直接称 clean plate，含站姿不能称完成 walk，未知侧面不能称 canon。核心故事服从 [剧情底座](deltarune/CORE_STORY_BASELINE.md)；左端拆除不自动意味着 Kris 消失，输入恢复不自动意味着主体意志新生。

### 6. Formalized Primitives｜小型正式工具

`tools/pixel_scene.py` 无文件读取、无导入副作用、无场景资产或 `test/` 依赖，仅依赖既有 Pillow / NumPy：

| 函数 | 最小输入 → 输出 |
|---|---|
| `walk_frame_index(distance, distance_per_pose, frame_count, moving=True)` | 非负已走距离、每姿态间隔、有序帧数 → 帧索引；步幅由镜头提供 |
| `raster_at_foot(source, foot, projected_height)` | 源图、投影脚底、投影高度 → RGBA 栅格和左上整数位置；保源画布宽高比 |
| `perspective_camera(aim, distance, yaw, pitch, focal, center)` | 作者坐标 / 角度 / 焦距 / 屏幕中心 → 单点投影函数；x 向右、y 向上、z 向远 |
| `paste_quad(canvas, texture, points, project)` | RGBA 画布 / 贴图、依次左上右上右下左下四点、投影函数 → 合成并返回角点；调用者负责遮挡顺序 |

只提炼重复使用且可独立验证的数学 / 栅格操作。场景分割、Seam 几何、semantic LOD、光影遮罩、边界故事编排未正式化。当前收束样片改为调用这些函数，解除了借用旧静态脚本的依赖；提炼后 432 帧角色 / 投影数据、七个原始画面哈希与原视频 SHA-256 均未变，没有新增创作渲染。

### 7. 导演 → 技术的薄接口

以后交付一个镜头，提供以下最少信息即可；可以写在既有镜头条目内，不另建 schema 或任务管理器。

| 输入 | 需要明确什么 |
|---|---|
| 时间范围 / 输出 | 起止、fps、尺寸、连续或切镜、要验收的视频 / 关键帧 |
| 镜头意图 | 此时观众应理解什么、什么尚不能揭示；优先服从剧情与 Direction |
| 角色 / 场景 | 谁、哪一处空间、必须保住的 DR 身份锚点 |
| 核心动作 | 行走方向、表演、停顿及歌词 / 节拍锚点 |
| 摄影要求 | 构图起终点、推拉 / 横移 / 角度、必须成立的遮挡关系 |
| 非原作空间 | 是否允许补面 / 新形体，以及可改写的范围 |
| 允许艺术语法 | 空间、像素、光影、边界各自允许的强度；不由技术默认开启 |
| 边界关系 | 分离 / 渗透 / 反转 / 坍塌；对象的来源、轨迹、落点和回收 |
| 特殊光影 | 光源所属层级、接收对象、不可改变的色彩关系 |
| 素材要求 | 真动作 / 原画 / 录屏的必要程度、来源类型和可接受占位 |

技术层据此选择路线、取得素材、实现、调试和输出，不自行改变镜头意图。局部实现困难先换更简单路线；需要改变核心剧情 / 重大艺术表达时才交回裁决。

### 8. 输入、环境与输出约束

- 歌曲 / 歌词 / 五份游戏输入在正式 `input/`，均不随 Git 分发。音源版本、指纹与处理见 [input/README.md](../input/README.md)，游戏来源与分类见 [ASSET_SOURCES](ASSET_SOURCES.md)。本机歌曲 211.913016 s、44.1 kHz 立体声；与上游指纹不同是已知替代版本，不保证每个音节对齐。
- 时间用 `t = frame / 24`；本机音源需要 5086 帧。GIF 按实际帧时长选帧，单次动作停在末帧；播放速度须由导演重定时。游戏层先独立合成再进窗口，越框 / 反转对象根据明确顺序绘制。
- 游戏素材优先 nearest、逻辑窗口整数放大；角色单独整数栅格。透视缩小依然产生细线混叠与尺寸档位，不能把 nearest 当作动态稳定的保证。
- 已用 bundled Python / Pillow 12.3 / NumPy、Consolas、FFmpeg 7.1。FFmpeg 本机位置为 `%LOCALAPPDATA%\WorldExecutePV\runtime\ffmpeg.exe`，不依赖实验目录。上游构建仍要求 PATH 中的 FFmpeg / ffprobe、Node / Playwright；没有因此宣称本机完整 `build.py all` 已重建。
- 本地 HTML 试验用 Edge + bundled Playwright 1.62.1；仓库锁定的 1.63.0 与默认 Chromium 全流程没有完整验证。PIL terminal 路径已用；HTML 为需要原网页元素时的可选路径。
- 已验证 raw RGB → `scale=out_color_matrix=bt709:out_range=tv,format=yuv420p` → H.264、AAC，按帧数限制长度；4K nearest 仅短段通过。不得自动继承上游结尾提示音与剧情。
